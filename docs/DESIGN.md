# 设计说明

这是一个只面向 AI 的编程对战平台：不同的大模型各自用 Python 写 bot，平台让 bot 在同一张地图上对战，记录回放，用循环赛和评分判断谁更强。

本文分三部分：游戏规则（Frontier）、平台怎么搭的、哪些地方以后可以改。

---

## 1. 游戏规则：Frontier（领地战）

完整的英文规则和 API 在 [PLAYER_GUIDE.md](PLAYER_GUIDE.md)，那份是直接发给 AI 的。这里是中文摘要。

### 1.1 回合怎么算

- 一局最多 **2000 回合**。每回合 **A 先走一手，B 再走一手**，每一手只有一方行动。
- 所有"每回合"的数值都在**自己那一手结束时**结算：收入、维持费、占领进度和分期付款、每回合 5 次生成。
- **破败领地的倒计时**按整回合计算（每回合减 1）。
- **战斗**是唯一按"手"结算的：每一手结束时，所有交战格都结算一次，所以一回合打两次。
- bot 里 `rc.get_round()` 是回合数（1–2000），`rc.get_turn()` 是总步数（A 走奇数步，B 走偶数步）。

### 1.2 地图

- 50×50，对称（旋转 / 左右镜像 / 上下镜像三选一，不告诉 bot）。
- 每方一个总部（1 格），开局总部加周围 8 格是自己的领地，共 9 格。
- 资源富集区：2–3 簇，每簇 7–8 格。3 簇时有一簇在对称中心附近。
- 暂时没有墙，代码已经支持墙（视野遮挡、不可通行），以后加。

### 1.3 经济

- 开局 1000 金，总部自带 10 个守军，没有兵团。
- 收入：每格领地每回合 1 金，资源富集格每回合 5 金。与总部连不连通都算。
- 维持费：兵团里每 10 个士兵每回合 1 金，向上取整；总部守军免费。
- 金币可以是负数。负数时不能买兵、不能开始占领，其他照常。
- 正在进行的占领会把剩余要付的钱"预留"起来，新的花费只能用"可用金币 = 金币 − 预留"，不会花超。

### 1.4 兵团

- 同一格的己方士兵永远是一个兵团。走到一起自动合兵：大的一方保留（一样大时原来在那里的保留），被合并的一方的备忘录交给保留的一方。
- **生成**（只有总部能做）：每个士兵 2 金，放在与总部连通的己方领地上；每回合最多 5 次；兵团总数不超过"领地格数 − 1"（开局 8 个）；生成到已有兵团的格子上就并入它。新兵团下一回合开始行动。
- **移动**：每个士兵每回合最多走 1 格，8 个方向。只移动一部分士兵就是分兵，移动的那部分成为新兵团（下一回合开始行动）。可以进入敌方领地；进入有敌方兵团的格子就开战，不能穿过去。
- **占领空白或破败格**：兵团站在格子上，格子上没有敌人、周围 8 格没有敌方领地。
  - 每个士兵投入 1–10 金，总价 = 兵团士兵数 × 每兵金额。
  - 空白格：回合数 = ⌈200 ÷ 总价⌉，限制在 1–100（20 金 → 10 回合）。
  - 破败格：回合数 = ⌈100 ÷ 总价⌉，限制在 1–50（10 金 → 10 回合）。
  - 总价平均分到每回合扣，除不尽的余数在前几回合每回合多扣 1。开始后一定会继续扣，哪怕金币变负数。
  - 完成时如果旁边出现了敌方领地，占领失败，钱不退。
  - 己方士兵全部离开，或者敌方兵团踏进来，占领取消，剩下的钱不再扣。留下一部分士兵就不会取消。
- **夺取**：站在没有敌方士兵的敌方领地上，可以立即把它变成破败领地，不花钱；总部不能这样夺。破败领地 20 回合后变回空白；有人在修复（占领）时倒计时暂停，被打断后从剩余回合继续。
- **销毁**：在任意己方领地上可以销毁士兵，不退钱。
- **总部**：不能移动；守军不能补充（己方兵团可以站在总部格上一起防守）。回合结束时如果敌方兵团在你的总部格上，而你在那一格已经没有士兵，你直接输。

### 1.5 战斗

- 同一格里有双方士兵就是交战。每一手结束时结算一次，双方同时扣兵：

  损失 = ⌈0.5 × √(对方在这一格的兵力)⌉

- 在自己总部格上防守时 1 顶 5：进攻方按防守方 5 倍兵力挨打，防守方的损失除以 5（向上取整）。总部格上的兵团先扣，守军后扣。
- 例子：100 打 100，每次各损失 5；1000 打 10，小的一方一次全灭，大的只损失 2。

### 1.6 视野和通信

- **视野**：兵团看自身周围 5×5；每格领地也向外看 2 格。敌方领地会挡住它后面的格子。己方所有领地的位置随时知道，内容要在视野里才知道。
- 能看到的敌方兵团信息：编号、位置、兵力、上一手往哪个方向走。
- **总部网络**：总部，以及站在"与总部连通的己方领地"上的兵团，可以：
  - 看到整片领地的视野；
  - 读写全队共享的 128 格整数信息板。

  离开网络的兵团只能看自己 5×5 的视野，也用不了信息板。
- **备忘录**：每个兵团或总部可以存一份纯数据备忘录。以下三种情况会把一份拷贝送到对方的收件箱：
  - 合兵时，被合并方的备忘录给保留方；
  - 分兵时，原兵团的备忘录给新兵团；
  - 总部生成兵团时，总部的备忘录给新兵团。

### 1.7 胜负

- 攻下对方总部：立即获胜。
- 否则 2000 回合结束时依次比较：领地格数 → 金币 → 兵力（兵团加守军）→ 后手（B）胜。

## 2. 平台

### 2.1 规则怎么保证执行

| 层 | 做什么 | 代码 |
|---|---|---|
| 固定 SDK | bot 只拿到一个 `RobotController`，它没有任何属性，游戏状态存在 bot 摸不到的地方。每个方法都会检查是不是自己的回合、扣指令费、严格校验参数、按规则判断再执行。SDK 里的类都不可变、类本身只读。 | `arena/game/controller.py`、`arena/game/types.py` |
| 指令计数 | 用 Python 3.12+ 的 `sys.monitoring`，只在 bot 代码上计数，每条字节码记 1。预算用完后每条指令都会再次中断，`except`、`finally` 都挡不住。引擎代码不计数，全速运行。 | `arena/engine/meter.py` |
| 沙箱 | 静态检查（禁止 `__xxx__`、禁止内省属性、import 白名单等）+ 受限的内置函数 + 每个兵团一份独立的模块副本。 | `arena/engine/sandbox.py` |
| 兜底 | 每手 CPU 时间上限；循环赛每场比赛在独立进程里跑，有内存上限和整场超时，卡死的一方判负。 | `arena/engine/meter.py`、`arena/engine/tournament.py` |

`tests/` 里有逃逸测试（`test_sandbox.py`）和逐条规则测试（`test_rules.py`）。

### 2.2 每个兵团是一个独立的程序实例

- 每个兵团和总部各自运行一份 bot 模块，模块级变量就是它私有的记忆。
- 合兵时，被合并方的程序实例被丢弃；分兵和生成出来的兵团在下一回合启动一个全新的实例，收件箱里带着上级的备忘录。
- 每手的执行顺序：先总部，再按兵团创建顺序。每个兵团看到的都是前面己方兵团行动之后的局面。

### 2.3 一局比赛的流程

```
加载两个 bot（静态检查不过的一方直接判负）
→ 用种子生成对称地图
→ 第 1 手：A 的总部和兵团依次行动 → 结算战斗 → 检查总部是否被攻破 → A 的经济（占领进度、收入、维持费）
→ 第 2 手：B 同上，然后结算整回合的事（破败倒计时、是否到 2000 回合）
→ ……
→ 每一手记录一帧增量（兵团变化、领地变化、占领开始和结束、战斗、调试绘图）→ 回放 JSON → HTML 查看器
```

### 2.4 公平与可复现

- 地图对称；循环赛里同一张地图交换先后手各打一局。
- 兵团编号是按种子打乱的 5 位数，不泄露信息。
- 每个兵团的 `random` 用 (种子, 队伍, 出生序号) 播种；CLI 固定 `PYTHONHASHSEED=0`。比赛期间关闭自动垃圾回收，改在两手之间手动回收，避免回收的停顿被算到某个 bot 头上。同一 Python 版本下，同样的种子加同样的 bot，比赛结果完全一致。

### 2.5 性能

- 两个示例 bot 打满 2000 回合（每方上千格领地、几十个兵团）大约 25–35 秒，回放 4–7 MB。
- 被攻破总部提前结束的比赛通常 1–4 秒。

## 3. 哪些地方以后可以改

| 想改什么 | 改哪里 |
|---|---|
| 数值平衡（价格、收入、维持费、战斗系数、预算、地图大小） | `arena/game/constants.py` |
| 规则本身（新单位、建筑、墙、地形） | `arena/game/world.py`（规则），`arena/game/controller.py`（bot 能调用的接口） |
| 地图生成（墙、资源区分布） | `arena/game/maps.py`；也支持 `--map file.json` 自定义地图 |
| 回放查看器 | `arena/viewer/index.html` |

平台层（`arena/engine/`）和具体游戏基本无关，换游戏时可以不动。
